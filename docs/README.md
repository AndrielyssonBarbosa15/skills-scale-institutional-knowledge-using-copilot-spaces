# OctoAcme Project Management Docs

This folder is the single entry point for OctoAcme's project management documentation. It gives new teammates and stakeholders a concise view of how projects move from initiation through planning, execution, release, and retrospective improvement, with an emphasis on small, testable increments, clear ownership, and measurable outcomes.

OctoAcme's workflow starts by defining the business need, success metrics, stakeholders, timeline, and early risks in a lightweight one-pager. Once work is approved, teams plan by building a prioritized backlog with acceptance criteria, estimates, dependencies, milestones, and a documented Definition of Done. During execution, teams track work on a visible board, use pull requests and CI checks to manage change safely, and review progress regularly before releasing with verification, communication, and rollback readiness in place.

Delivery is shared across Project Managers, Product Managers, Developers, QA/Testing contributors, and Stakeholders. Project Managers coordinate plans, risks, and communication; Product Managers set priorities and outcomes; Developers implement and estimate work while surfacing technical risks; QA/Testing validates quality and acceptance criteria; and Stakeholders provide inputs, approvals, and feedback. The operating model relies on regular standups, weekly syncs, status updates, demos, structured risk escalation, and a single source of truth for project status and decisions.

Quality assurance is built into the lifecycle rather than treated as a final step. OctoAcme expects unit tests for new logic, integration tests where appropriate, smoke tests for critical flows, CI checks for automation and security scanning, and pull requests that stay focused, link back to issues and acceptance criteria, and receive review approval before merging.
